# 当前决策

## 独立项目与知识边界

用户要求在父目录下新建子目录克隆自己的 fork；本项目独立管理 Git、
CM 与记忆，不成为 XCS 的子项目，不导入 XCS/XAPS 的活动数据库。
其他源码包仅作参考。XAPS 人工校准结果可作为未来语义输入，未重构代码
不能充当重构后的验收证据；Yuto 是另一条独立的后续试点。

## 单入口与有界恢复

采用 `INDEX + 专题 + 单一 checkpoint + Git 历史`。借鉴热/冷分层与
容量巡检，避免第二套 PROJECT_HANDOVER、固定最低行数和自动提交钩子。
容量预警只提示整理；未决事项、适用条款与来源不得为缩短文件而丢失。

## 当前服务与未来扩展

先使用已有 CM API 做经验检索、明确记录与人工校准；不把 `caused`
强用为“实现/验证/细化”关系。六视图工程模型、版本化证据与说明书裁剪
见 [设计提案](../../docs/engineering/integrated-design.md)，不是已接受的接口合同。
修改引擎前先完成一个受控逆向切片，按缺口决定扩展，保持现有 API 兼容。

## 发布边界

普通源代码 Git 发布不携带本机 CM DB、索引或原始会话。
CM 自身的 snapshot/commit/push/import 与外层 Git 是不同操作，另需明确范围。
已授权的具体提交/推送可直接完成，不在工作流中重复增加审批步骤。
