## 待校准问题

旧参考包的静态检查提出以下线索，均不是本 checkout 已复现缺陷：

- 替换的“原子性”指串行最终状态，还是故障/并发下整组原子提交？
- 普通重录旧值允许恢复有效；是否需要每个 scope/key 仅有一个当前值？
- 同 key 的 user/agent scope 是否应保留独立身份？产品 scope 不能代替客户范围。
- 统一检索文案与传播/RRF 分支的关系、全局 limit 和完整性承诺是什么？

示意场景：记录 user/package_manager=npm 与 agent 同值，随后对 user
替换为 pnpm，再重试及普通重录 npm。为每步登记有效值集合、身份和历史，
先由源码建立候选预期，再由人工确定目标合同；不对活动知识库执行该试验。
事务、并发与失败恢复需要独立验收，不能由带 atomic 的测试名称证明。
